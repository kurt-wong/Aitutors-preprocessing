## 2. CONTRADICTION(与 Frozen 件/既有事实的直接冲突)

**C-1(cp1/2,Owner 特别注意的技术化表述)**:若 L2 模型把 **review_trail 本身**定义为 Evidence Authority,则与 **75 §三 R4("只有 ValidationEvent 产生 Evidence Authority",冻结规则,变更需架构审查)** 直接冲突。合法出路只有两条,设计稿必须二选一并引证:
(a) 正式修订 R4(架构审查路径,留痕);或
(b) 人工 review 经 **ValidationEvent(validation_method="human_review")** 产生 authority——槽位已存在(O-8),生产者未建;此时 review_trail 只是该事件的输入证据,不是 authority 本体。
**在设计稿给出 Frozen Spec/L2 依据前,DSH 不接受 "review_trail 即 authority" 的无依据断言。**

**C-2(cp12)**:R5 字面("Semantic IR 只能引用 ValidatedEvidence")与实际流水线顺序(O-9)矛盾——IR 在 validation 之前构造。模型必须显式二选一:①重构顺序(validation 前置于 IR 构造);或 ②把 R5 enforcement 点改述为 **IR→下游(Knowledge Asset)的消费边界**而非构造时点。**禁止第三种做法:纸面写 "IR boundary check" 而实际顺序未变**——那正是 P3.2 抓获的"机制存在但不被依赖"模式的镜像。

## 3. ATTACK(具体攻击面,可复现路径)

**A-1(cp7/11)claim_id 跨文档碰撞 → 跨卷 authority 复用。**
每份卷都有 "Q1"。Phase 1 由 per-run 内存隔离掩盖;一旦 Phase 2 按 claim_id 持久化 authority 台账而键不含 (source_version, annotation) 作用域,**`is_evidence_validated("Q1")` 会因另一份卷的 Q1 已验证而返回 True**。任何持久化设计若不先解决 O-1 的键作用域,即在此攻击面裸奔。

**A-2(cp9/1)authority-by-presence:最弱 authority = 一次无认证 POST。**
空 entry `{decision:"approve", verified_by:"human"}` 即满足 `_has_human_approve`;reviewer_id 可任意伪填;confirmed_fields 不校验(O-5)。若 review_trail 成为 authority,系统最弱环节是一个未认证端点写入的字符串。

**A-3(cp6)authority 与内容解耦 → 陈旧 authority 洗白。**
authority 记录无内容指纹(O-7)。任何离线改写 payload 的路径(迁移/回填工具;两侧均有此类工具先例)发生后,review_trail/ValidationEvent 仍对**不同内容**宣称 approved。攻击成立条件 = 只要出现一次带外 payload 写入。

**A-4(cp10)INVALIDATED 历史必然蒸发。**
75 冻结语义要求"source 变更/OCR 升级/bug 修复 → append INVALIDATED,永不改历史"。内存台账重启即失(O-4):重跑后 gate 重新得出 auto_approve → 新内存台账里 claim 重新 validated,**invalidation 审计链在 Phase 1 基质上不可能存在**。任何基于当前基质宣称 event-sourced authority 的设计 = UNPROVEN 直到持久化落地。

**A-5(cp7)golden 冒名面。**
`_HUMAN_SOURCES = {human, golden}` 由调用方断言(`admission.py` L47;reject 的 source 参数同)。API 今天硬编码 "human",但**无结构性阻碍**让未来任何进程内调用方自称 golden,直接获得最高 authority 等级。

## 4. UNPROVEN(设计稿不得默认继承的未证前提)

**U-1(cp11)**:claim_id → candidate_id **不存在**正式、唯一、可验证的 identity join(O-1)。le_hash 的 input_domain 含 annotation_id+unit_id、理论上可派生,但未存储为 join;"存在 identity join"的声明须设计+迁移证据。

**U-2(cp12)**:defense-in-depth 的**独立性未证**。当前 ValidationEvent 与 gate_decision 是同一次 `evaluate()` 输出的两种记法(`service.py` L183-197;`record_validation` 直接消费 gate dict)——两个边界检查若同根于一次评估,是**重复检查,不是纵深防御**;evaluate() 的缺陷同时穿透两层。真纵深需要第二个**独立计算/独立证据源**(如 Admission 时对 Source bytes 的再验证)。

**U-3(cp2)**:human/golden review 与 ValidationEvent **今天不是同一 abstraction**:持久性(内存 vs DB)、生命周期(状态机 terminal vs 无界 append)、绑定(reference_ids vs 无)、生产者(确定性 gate vs 无认证 API 字符串)四项全不同(O-2~O-5/O-8)。统一声明必须附对账表,不得凭名字合并。
